# ubersdr_airsplice

Automated multi-channel audio recorder for [UberSDR](https://ubersdr.org) — connects to a remote UberSDR instance, tunes any number of channels simultaneously, and records demodulated audio to WAV files with a live web UI for playback, management, and monitoring.

---

## How it works

```
UberSDR (remote SDR) --► ubersdr_airsplice (Go) --► WAV recordings
                                 |
                                 └──► web UI  http://<host>:6095
```

- **`ubersdr_airsplice`** — Go service that connects to UberSDR via WebSocket, streams demodulated audio per channel, and writes it to segmented WAV files
- **Smart Record (VOX gate)** — optional SNR-gated recording: only writes audio when signal strength exceeds configurable thresholds, with hysteresis hold timers and pre-roll buffering
- **Scheduler** — optional time-based recording windows per channel (daily, day-of-week, date-range, midnight-spanning)
- **Web UI** — live channel status, SNR meters, FFT spectrum, audio preview, session browser with SNR telemetry timeline, download and delete; served on port 6095

Channels are managed entirely through the web UI and persisted to `channels.json` — no restart required to add or remove a channel.

## Quick start (Docker — recommended)

```bash
curl -fsSL https://raw.githubusercontent.com/madpsy/ubersdr_airsplice/main/install.sh | bash
```

This will:
1. Create `~/ubersdr/airsplice/` and download `docker-compose.yml` and helper scripts
2. Generate a random UI password and inject it into `docker-compose.yml`
3. Create the `recordings/` output directory
4. Pull the latest `madpsy/ubersdr_airsplice` image
5. Start the service

Then edit `~/ubersdr/airsplice/docker-compose.yml` to set your UberSDR URL, and run `./restart.sh`.

Open `http://<host>:6095` to access the web UI.

## Configuration

All configuration is via environment variables in `docker-compose.yml`:

| Variable | Default | Description |
|----------|---------|-------------|
| `UBERSDR_URL` | `ws://ubersdr:8080/ws` | UberSDR WebSocket URL |
| `UBERSDR_PASS` | _(empty)_ | UberSDR bypass password |
| `UI_PASSWORD` | _(empty)_ | Password for write actions in the web UI (auto-generated by `install.sh`) |
| `OUTPUT_DIR` | `/data` | Output directory for recordings inside the container |
| `WEB_PORT` | `6095` | Web UI port |
| `SEGMENT_SECS` | `300` | Rotate to a new WAV file every N seconds; `0` = one continuous file per session |
| `CLEANUP_ALL_DAYS` | `30` | Delete ALL recordings older than N days; `0` = disabled |
| `MAX_STORAGE_MB` | `20480` | Maximum total storage in MB across all channels; `0` = unlimited |
| `CLASSIFY` | `false` | Classify closed segments as voice / music / noise — see [Analysis](#analysis-optional) |
| `CLASSIFY_MODEL` | `mn10` | Classifier: `mn05`, `mn10`, `mn20` (EfficientAT) or `dsp` (no model) |
| `CLASSIFY_THREADS` | `1` | CPU threads for the classifier |
| `TRANSCRIBE` | `false` | Transcribe closed segments with Whisper |
| `WHISPER_HELPER` | `whisper-helper` | Path to UberSDR's `whisper-helper` binary |
| `WHISPER_MODEL` | `base` | `tiny`, `base` or `small` |
| `WHISPER_THREADS` | `2` | CPU threads for Whisper |
| `WHISPER_SPEED` | `1.0` | Feed audio to Whisper at this multiple of real time (0.5–8) |
| `MODEL_DIR` | `<OUTPUT_DIR>/models` | Where downloaded models are kept |

Channels are **not** configured via environment variables — they are added and removed through the web UI and persisted to `channels.json` in the output directory.

## Web UI

Open `http://<host>:6095` in a browser to access:

- **Channel list** — live status for every active channel: frequency, mode, connection state, recording state, SNR meter
- **FFT spectrum** — real-time audio spectrum display per channel
- **Live audio preview** — stream the demodulated audio for any channel directly in the browser
- **Session browser** — recordings grouped by channel and date, with total duration and average SNR; paginated by UTC calendar day
- **SNR telemetry timeline** — per-session SNR/level chart built from the `.jsonl` telemetry log
- **Download** — stream any session or individual segment as a WAV file
- **Delete** — remove individual segments or entire sessions (requires UI password)
- **Retention & quota settings** — configure per-channel or global retention hours and storage quotas from the UI
- **Analysis** (optional) — per-channel classification and transcription settings; each segment shows its voice / music / noise label and, when transcribed, a 📝 button that opens the transcript

## Recording modes

### Continuous (default)

Audio is written to disk from the moment the channel connects. A new WAV segment is opened every `SEGMENT_SECS` seconds (default 5 minutes). Set `SEGMENT_SECS=0` for one unbroken file per session.

### Smart Record (VOX-style SNR gate)

When enabled per channel, the recorder monitors the rolling SNR and applies a two-threshold hysteresis gate:

| State | Transition |
|-------|-----------|
| **Idle** | SNR rises above `start_thresh_db` → Arming |
| **Arming** | SNR stays above threshold for `start_hold_sec` → Recording (pre-roll audio included) |
| **Recording** | SNR falls below `stop_thresh_db` → Tail |
| **Tail** | SNR stays below threshold for `stop_hold_sec` → Idle (segment closed) |

An optional `max_record_mins` cap closes the segment and returns to Idle if a single activation runs too long.

#### SNR scale (changed in the audio protocol v4 migration)

Thresholds are a **true SNR in dB**. Defaults are `start_thresh_db` **10** and `stop_thresh_db` **5**.

What the scale looks like on a real receiver, measured on 2026-09-03 at the 2.4 kHz SSB passband:

| Condition | Median | p95 | Max |
|-----------|--------|-----|-----|
| Empty channel (6 captures, ~20k packets) | −0.8 … +2.0 | ≤ 3.8 | 9.3 … 12.9 |
| Normal SSB QSO (7.150 MHz) | 7.95 | 12.94 | 16.43 |
| Strong signal (measured at 12 kHz USB) | 32.67 | 35.19 | 42.40 |

An empty channel reads about **0 dB**, which is what a true passband SNR should do. The defaults were set from these populations rather than by rescaling the old numbers: 10 dB is above every idle capture's p99 (≤ 7.1) while still catching a normal QSO, and 5 dB is above idle p90 (≤ 3.8) so the stop countdown can actually complete. The hysteresis gap is **5 dB, not the old 15** — at 2.4 kHz there is only about 10 dB between the top of the idle spread and a sustained normal QSO, so a wider gap would put one threshold on the wrong side of its population. If you only want strong stations, raise `start_thresh_db`; a strong signal sits near 30 dB.

They used to be 50 and 35. On audio protocol v2 the server sent the noise *density* N0 in dBFS/Hz while baseband power is integrated over the whole passband, so `baseband - noise` was not an SNR at all — it read `10*log10(passband Hz)` too high, and drifted whenever the filter width changed. From v3 the server sends the noise power inside the demodulator passband, so the subtraction is a real SNR and every reading is lower by:

| Mode | Passband | Correction |
|------|----------|-----------|
| CW | 500 Hz | 27.0 dB |
| USB/LSB | 2400 Hz (2.7 kHz default) | 33.8 dB |
| USB/LSB | 2950 Hz (radiod preset, no bandwidth set) | 34.7 dB |
| AM/SAM | 5000 Hz | 37.0 dB |
| FM/NFM | 8000 Hz | 39.0 dB |

> **Carrying thresholds over from a pre-v4 build?** Subtract the correction for your mode — about **34 dB** on SSB. A threshold left on the old scale sits ~34 dB above anything the server will now report, so the gate never opens and the channel silently records nothing.

### Scheduled recording

When enabled per channel, recording only occurs within configured time windows. Each schedule rule can specify:

- Daily time window (`start_time` … `stop_time`, 24-hour `HH:MM`; midnight-spanning windows supported)
- Day-of-week filter (0 = Sunday … 6 = Saturday; empty = every day)
- Absolute date range (`from_date` … `to_date`, `YYYY-MM-DD`; empty = unbounded)

Multiple rules are combined with OR logic. The timezone is configurable per channel (IANA name, e.g. `Europe/London`; defaults to UTC).

Smart Record and Schedule can be combined: the schedule gate controls *when* the channel is eligible to record, and the VOX gate controls *whether* there is signal worth recording within that window.

## Analysis (optional)

Two optional features work on each segment after it closes, in the background, without holding up recording. **Both are off by default.** Each needs two switches:

1. **On the host** — `CLASSIFY=true` and/or `TRANSCRIBE=true`. While a feature is off nothing is loaded, downloaded or started for it.
2. **On the channel** — in the channel's ⚙ Settings, under *Analysis*. A new channel opts in to nothing, so enabling a feature on the host never starts work on a channel by surprise.

The model is chosen once per host, so one model is loaded and results mean the same thing on every channel. In the UI, an option that is off on the host is shown disabled with the setting that turns it on; the channel's saved choice is kept and applies once the feature is enabled.

### Classification

Labels each segment **voice**, **music**, **voice + music** or **noise**, with the share of windows in each. The rules for turning sounds into those four labels are [NightDX](https://github.com/marcozennaro/nightdx)'s (MIT, © Marco Zennaro).

| `CLASSIFY_MODEL` | What it is | Download | CPU per 10 s of audio* |
|---|---|---|---|
| `mn05` | EfficientAT, width 0.5 (AudioSet mAP .443) | 5.9 MB | ~0.1 s |
| `mn10` (default) | EfficientAT, width 1.0 (mAP .471) | 19.7 MB | ~0.15 s |
| `mn20` | EfficientAT, width 2.0 (mAP .478) | 71.9 MB | ~0.6 s |
| `dsp` | NightDX's model-free classifier | none | negligible |

\* one thread, x86-64 with AVX2, measured on a busy host.

**EfficientAT** ([github.com/fschmid56/EfficientAT](https://github.com/fschmid56/EfficientAT), MIT, © Florian Schmid) are MobileNetV3 audio taggers trained on Google's AudioSet (527 sound classes). They replace the AST transformer NightDX uses (mAP .459) at a small fraction of its cost. airsplice runs them in pure Go, with AVX2/FMA (amd64) and NEON (arm64) kernels for the convolutions; the weights are the official release files, downloaded into `MODEL_DIR` on first start and checked against a pinned size and SHA-256 — no conversion step and no Python. Each 10-second window is tagged, and the strongest voice, music and noise tags among its top 40 decide that window, as in NightDX. The strongest radio-relevant tags ("Speech", "Radio", "Static", …) are kept with the result and shown on hover. If the model cannot be downloaded or loaded, segments are classified with `dsp` instead and the result says so.

**`dsp`** is a port of NightDX's model-free classifier: spectral flatness, syllabic (2–8 Hz) loudness rhythm and spectral steadiness over 5-second windows, with NightDX's thresholds. Its measurement band is NightDX's 250–3500 Hz capped at the channel's audio passband; without the cap an SSB filter's skirt falls inside the band and makes an empty SSB channel read as music. It is much weaker than the models: data modes such as FT8 read as music, and it was checked on only a handful of SSB recordings.

**SNR rule.** Whichever classifier runs, a segment whose average passband SNR is below 3 dB is noise whatever the classifier hears in the hiss (an empty channel reads about 0 dB on the v4 scale). The label's backend then ends in `+snr`.

### Transcription

Runs [UberSDR's `whisper-helper`](https://github.com/ka9q/ubersdr) — whisper.cpp with Silero voice-activity detection, the same recogniser the UberSDR desktop client uses — as a child process at low CPU priority. airsplice does not ship it: build it from `clients/electron/whisper` in the UberSDR tree (it is statically linked, one file per platform) and set `WHISPER_HELPER` to its path, or mount it into the container. If it is missing, transcription reports itself unavailable in the UI rather than failing silently.

The Whisper model and the VAD model are downloaded on first start into `MODEL_DIR`, from Hugging Face URLs pinned to a commit and checked against a pinned size and SHA-256 (the same pins as UberSDR's `models.json`). `base` is about 60 MB, `tiny` 32 MB, `small` 190 MB.

Per channel you choose the **language** (or automatic detection) and whether to **only transcribe segments classified as voice** (which needs classification on for the channel too).

Whisper's helper is built for live audio: it skips audio once it is more than 10 s behind. Segments are therefore fed at `WHISPER_SPEED` × real time, one at a time; a transcript the helper fell behind on is marked *partial*. At the default 1.0 one helper keeps up with one channel's worth of continuous audio — transcription suits VOX and scheduled channels best. When the queue (32 segments) is full the oldest waiting segment is skipped.

### Results

Results are stored in each segment's `.json` sidecar under `analysis`, and pushed to the UI as they arrive:

```json
"analysis": {
  "classification": { "status": "done", "label": "voice", "voice_pct": 80, "music_pct": 0, "noise_pct": 20,
                      "backend": "mn10", "confidence": 0.84, "windows": ["voice", "voice", "voice", "voice", "noise"],
                      "tags": ["Speech", "Radio", "Male speech, man speaking"] },
  "transcript": { "status": "done", "language": "en", "model": "base", "text": "…", "lines": ["…"], "partial": false }
}
```

`status` is `pending`, `done`, `skipped` or `failed` (with a `reason`). Segments under 2 s are skipped. Work still pending at shutdown is picked up again on the next start. `GET /api/analysis` reports what the host offers: whether each feature is enabled, the model, each one's state (`starting`, `downloading`, `ready`, `unavailable`, `failed`) and the queue lengths.

## Output files

Each completed recording segment produces three files in the output directory:

| File | Description |
|------|-------------|
| `<uuid>.wav` | PCM audio (mono S16LE, sample rate from UberSDR) |
| `<uuid>.json` | Segment metadata (label, frequency, mode, timestamps, duration, SNR stats, and [analysis](#analysis-optional) results when enabled) |
| `<uuid>.jsonl` | Telemetry log: one JSON object per line, appended every ~10 s while recording — `{"t":"<ISO>","snr":{...},"level_dbfs":<f32>}` |

A session-level sidecar (`session_<uuid>.json`) is also maintained, grouping all segments that belong to the same continuous recording session.

Orphaned WAV files (e.g. from a crash before the segment was closed) are automatically recovered on startup by reading the WAV header.

## Storage management

### Age-based cleanup

Recordings older than the configured retention period are deleted automatically every 5 minutes. Retention can be set globally (default hours) or per channel, and is configurable live from the web UI without restart.

### Quota-based cleanup

When total disk usage exceeds the configured limit, the oldest segments are deleted first until usage is within the limit. Quotas can be set globally (`MAX_STORAGE_MB`) or per channel, and are also configurable from the web UI.

## Building from source

### Docker image

```bash
./docker.sh build          # build madpsy/ubersdr_airsplice:latest
./docker.sh push           # build and push to Docker Hub
./docker.sh run            # run locally (uses env vars)
```

Override the image name:
```bash
IMAGE=myrepo/ubersdr_airsplice:dev ./docker.sh build
```

### Go binary

Requires Go 1.21+

```bash
go build -o ubersdr_airsplice ./...
./ubersdr_airsplice \
    -url ws://sdr.example.com/ws \
    -listen :6095 \
    -output ./recordings
```

All flags:

| Flag | Default | Description |
|------|---------|-------------|
| `-url` | _(required)_ | UberSDR WebSocket URL |
| `-password` | _(empty)_ | UberSDR bypass password |
| `-listen` | `:6095` | HTTP listen address |
| `-output` | `./recordings` | Directory to save recordings |
| `-ui-password` | _(empty)_ | Password for write actions in the web UI |
| `-segment-secs` | `300` | WAV segment length in seconds; `0` = continuous |
| `-cleanup-all-days` | `30` | Delete recordings older than N days; `0` = disabled |
| `-max-storage-mb` | `20480` | Maximum total storage in MB; `0` = unlimited |
| `-classify` | `false` | Classify closed segments |
| `-classify-model` | `mn10` | Classifier: `mn05`, `mn10`, `mn20` or `dsp` |
| `-classify-threads` | `1` | CPU threads for the classifier |
| `-transcribe` | `false` | Transcribe closed segments |
| `-whisper-helper` | `whisper-helper` | Path to `whisper-helper` |
| `-whisper-model` | `base` | `tiny`, `base` or `small` |
| `-whisper-threads` | `2` | CPU threads for Whisper |
| `-whisper-speed` | `1.0` | Multiple of real time to feed Whisper |
| `-model-dir` | `<output>/models` | Downloaded model cache |
